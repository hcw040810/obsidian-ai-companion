# 仓库全面更新流程

当用户说"更新"、"整理"、"帮我更新一下"时，执行以下全部步骤，不要遗漏，不要让用户催第二次。

## 第一步：扫描所有笔记

遍历仓库所有 .md 文件（排除 .obsidian、.claude、附件），收集：
- 文件名、路径、大小
- frontmatter 中的 source 标签（判断是否为爬取文章）
- 文件内容

## 第二步：MOC 收录检查

对比 4 个 MOC 中已收录的 [[wiki链接]] vs 实际存在的笔记。

**需要收录的笔记：**
- 02 灵感随记 — 按主题分到对应 MOC
- 03 收集知识/抖音 — 按内容分到对应 MOC
- 04 和ai聊聊 — 按主题分到对应 MOC

**不收录的笔记：**
- 01 日记（按时间线管理，不加 MOC）
- 00 速记灵感、00 备忘（inbox，不加 MOC）
- 03 收集知识/AI变现/ 和 03 收集知识/前额叶/ 下的爬取文章（用户没看过，不加 MOC）
- 索引文件
- 占位符（文件大小 ≤ 3 字节）

**MOC 分类规则：**
- 心理状态/情绪/自我认知/身体 → MOC 心理与成长
- 思维框架/行动方法/学习/财富/消费 → MOC 思维与效能
- 人际关系/社交技巧/具体的人 → MOC 人际关系
- AI/技术/变现/工具/创业 → MOC AI与变现

## 第三步：MOC 描述同步

检查 MOC 中每条链接的描述是否与实际笔记内容一致。

**需要更新描述的情况：**
- 描述是"待补充"但笔记已有内容 → 更新为实际内容摘要
- 描述过时或不准确 → 更新
- 笔记为空/占位符 → 保持"待补充"或写"暂时忘了，待回忆补充"

## 第四步：交叉链接检查

扫描所有笔记内容，找出提到了其他笔记主题词但没有加 [[wiki链接]] 的地方。

**添加链接的规则：**
- 笔记 A 的内容提到了笔记 B 的主题关键词 → 在 A 中添加 [[B]]
- 只添加有意义的关联，不添加泛泛的词（如"状态"、"时间"）
- 不在爬取文章中添加交叉链接（用户没看过）
- 不在日记和 inbox 中添加交叉链接

## 第五步：死链检查

扫描所有 [[wiki链接]]，确认目标文件存在。
- 文件名变更时，全局搜索并更新所有引用
- 保持零死链

## 第六步：清理检查（仅针对爬取文章）

- HTML 实体（&lt; &gt; &quot; &#34;）→ 转成正常字符
- 图片链接（![alt](url)、<img>标签）→ 删除
- 裸 URL → 删除
- 来源标签（[知乎]、[B站专栏]）→ 删除
- 无意义的 markdown 链接 → 删除

## 第七步：索引更新

更新爬取文章文件夹的索引文件（00 索引.md），确保：
- 文件名与实际一致
- 按来源分类
- 统计数量正确

## 输出格式

更新完成后，给用户一个简洁的报告：
- MOC 新增/修改了多少条
- 添加了多少交叉链接
- 修复了多少问题
- 零遗漏确认
