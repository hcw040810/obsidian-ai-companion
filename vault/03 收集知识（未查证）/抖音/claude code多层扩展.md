视频介绍了 Claude Code 的多层扩展功能，从长期记忆到外部工具连接，帮助开发者提升效率。
Claude Code 扩展功能分层
CLAUDE.md：Claude 的“长期记忆”，每个会话自动加载，用于保存项目约定、构建命令、项目结构等需要“永远知道”的信息。
Skills：自定义技能包，可一键调用多步骤工作流，如输入 /deploy 自动执行一套部署流程。
MCP：连接外部服务的桥梁，可让 Claude 直接查询数据库、发送 Slack 消息等。
Subagents 和 Agent teams：负责将复杂任务拆分为小块并行处理。Subagent 是当前会话中的“临时工”，完成后汇报结果；Agent team 是多个独立会话，可互相发消息、自主协调。
Hooks：在特定事件发生时自动触发脚本，如每次保存文件后自动运行 ESLint 检查代码。
功能选择原则
不要一次性配齐所有功能，而是按需添加。
当发现某个操作重复三次以上，就应该考虑将其封装为扩展。
功能适用场景
如果 Claude 两次搞错项目约定（如总是用 npm 而不是 pnpm），将约定写入 CLAUDE.md。
如果三次重复粘贴同一套多步骤流程，将其封装为 Skill。
如果一直在从浏览器复制数据给 Claude，需要用 MCP 连接外部工具。
如果某个辅助任务的输出刷爆对话窗口，用 Subagent 将其隔离。
如果希望某些操作自动发生（如提交前自动跑测试），用 Hook。
易混淆功能对比

### Skill vs Subagent

Skill 是可复用的知识或工作流，可随时调用。
Subagent 是隔离的工作线程，适合处理大量文件或研究，只返回摘要，不污染主对话。
关键区别：Skill 是“知识”，Subagent 是“劳动力”。

### CLAUDE.md vs Skill

如果信息需要“永远知道”（如构建命令、项目结构），放在 CLAUDE.md。
如果只是偶尔需要参考（如 API 文档、部署清单），放在 Skill。
经验法则：CLAUDE.md 保持在 200 行以内，过长则拆分为 Skill 或 Rules 文件。

### Subagent vs Agent team

Subagent 是当前会话中的“临时工”，完成后汇报结果。
Agent team 是多个独立的 Claude 会话，可互相发消息、自主协调。
简单来说：一个人能完成的任务用 Subagent，需要团队协作的用 Agent team。

### MCP vs Skill

MCP 给 Claude 提供“能力”，如连接数据库。
Skill 则教会 Claude 如何使用这些能力，如在 Skill 中写明团队的数据库架构、常用查询模式和消息格式规范。
两者搭配使用，效果翻倍。

### Hook vs Skill

Hook 是“不需要 Claude 思考”的自动化，如每次保存文件自动格式化代码。
Skill 是“需要 Claude 推理”的工作流，如代码审查清单。
确定性操作用 Hook，需要判断和决策的用 Skill。
规则的强制执行
如果有一条规则需要“绝对不能碰”（如.env 文件），不要只写在 CLAUDE.md 里当“建议”，而要用 PreToolUse Hook 直接拦截，这才是真正的“强制执行”。
功能优先级与覆盖规则
扩展可以在用户级、项目级、插件级甚至子目录中定义。
当规则冲突时，Claude 会自己判断，通常更具体的说明优先。
子目录中的 CLAUDE.md 会覆盖根目录的通用规则。
Skills 和 Subagents 按名称覆盖。
MCP 服务器有优先级顺序。
Hooks 比较特殊，所有注册的 Hook 只要匹配事件都会触发，不会互相覆盖。
上下文成本与效率考量
每个扩展功能都会消耗 Claude 的上下文窗口，过多会导致窗口塞满、噪音增加，反而降低效率，甚至触发错误的 Skill 或忘记约定。
CLAUDE.md 每个请求都加载，成本最高。
Skills 只在调用时加载完整内容，平时只加载描述，成本较低。
MCP 工具默认启用搜索，空闲时几乎不占资源。
Subagents 完全隔离，不影响主会话。
Hooks 在外部运行，零成本。
典型工作流组合
CLAUDE.md 定规矩。
Skill 封装流程。
MCP 连接外部系统。
Hook 做自动化兜底。

### 核心观点


### Claude Code 的扩展体系可分为三层

Skills 管理需要“永远记住”的知识和工作流。
MCP、Subagents、Hooks 管理连接外部工具、并行计算和自动触发。
真实工作流通常是组合使用的，关键是按需添加，不要一上来就配置全套。当某个操作重复三次以上，就是将其封装为扩展的信号。
